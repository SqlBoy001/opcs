# 有限状态工作流

登记阶段只能使用下表枚举。`UNCONFIRMED` 是未经核实的已有项目标记，不是完成度；获得可信证据后再转入适用阶段。决策独立记录为 PENDING / GO / ITERATE / STOP。

| 阶段 | 工作与交付物 | 退出依据 |
| --- | --- | --- |
| IDEA | 记录用户问题、目标与项目卡片，登记项目 | 问题明确，进入 RESEARCH；或有理由 STOPPED |
| RESEARCH | 比较现成方案，定义 MVP、量化或可观察验收阈值、预算 | 范围与授权明确后 BUILD；不值得做则 STOPPED |
| BUILD | 在独立业务仓库实现并完成开发者自测，提供提交与产物 | 产物及自测证据齐备后 VERIFY；阻塞则留在当前阶段 |
| VERIFY | 基于真实产物做一次独立验收，记录功能、质量、成本与价值 | 达标后 CONTENT 或 DONE；范围内阻塞且允许返工则 ITERATE；否则等待用户或 STOPPED |
| ITERATE | 只修复已列明的 blocking issue，提供修复提交 | 定向复验通过后 CONTENT 或 DONE；熔断后等待用户决定 |
| CONTENT | 基于验证报告整理内容事实源，不夸大未测效果 | 有发布授权及发布验证证据时记录发布成功；无需发布也可 DONE |
| DONE | 保存证据、结论及完成理由 | 新证据需要回退时记录原因与授权 |
| STOPPED | 保存证据与停止理由，不继续自动执行 | 用户明确决定后才能继续 |

阶段无需机械走完：研究后可以 STOP；简单文档任务可直接由单执行者修改和自检，无需开发或验证 Agent。自检须标注为自检，不能冒充独立验收。业务效果的独立验收使用 [验收报告](../templates/validation.md)。DONE 不代表所有业务假设成立；STOPPED 也不表示假设必然被证伪。

执行边界与预算以 [循环策略](loop-policy.md) 为唯一来源：单任务交接最多 6 次、开发返工最多 2 次、完整 QA 最多 1 次、同一错误自动重试最多 2 次。首次 QA 可以全量检查；返工之后只能复验列明的阻塞问题及必要的核心 smoke test。阶段可以回退，自动返工仍受全部熔断条件限制，回退不清零计数。

## 跨仓交接

总控按需授权交接，执行者只提交结果和交接建议，不自行唤起下一个 Agent。只传任务 ID、目标与验收标准、项目仓库及分支/提交、产物路径、状态、阻塞问题和证据；不传整个聊天记录。预算及计数保留在同一任务记录中，供总控在交接前检查。

任何“发布成功”结论都必须有目标地址、发布版本、验证时间和实际访问/效果证据；仅上传命令成功不足以确认发布成功。没有发布授权时保留可审阅产物即可。
