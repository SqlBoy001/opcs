# 单任务循环与预算策略

本文件是上限与停止条件的唯一规则来源，V0 通过任务记录人工维护，不实现自动互相调用的 Agent 网络。

## 计数与权限

用户确认任务 ID、目标、路径范围、验收条件和预算时开始计数，所有计数初始为 0。任务首次分配不计交接。总控（本任务被明确指定的负责人；可为用户）有权发起后续交接；其他角色只能提交报告与建议。每次将执行责任交给另一角色或执行者记一次交接，返回总控也计一次；同一执行者的本地工具调用、自检和文档阶段切换不算交接。

| 计数项 | 默认软上限 | 定义 |
| --- | --- | --- |
| handoffs | 6 | 首次分配之后每次责任移交计 1 |
| development_reworks | 2 | 首次实现和开发者自测之后，因验收列明的阻塞问题重新修改实现，每一批修复计 1；首次开发中的正常修正不算返工 |
| full_qa | 1 | 首次覆盖全部验收范围的 QA 或最终全量自检计 1；开发者局部自测不算完整 QA |
| same_error_retries | 2 | 按错误签名记录；初次失败之后再次执行相同失败操作，每次计 1；更早触发连续同一问题规则时立即停止 |

执行前检查上限，执行后更新计数与证据。达到上限即输出 `AUTO_LOOP_STOPPED`，停止进一步自动循环；可交付当前结果。完整 QA 的额度耗尽意味着不得再次全量审计：首次 QA 若发现阻塞，转交用户决定是否授权定向返工，不能自行启动。用户授权继续也保留原任务累计计数及授权记录，不得自行“重置计数”或换任务 ID 绕过限制。

## QA 与定向复验

首次 QA 可以全量检查，输出 PASS / PARTIAL / FAIL / BLOCKED，并包含：

- `blocking_issues`：仅列验收范围内的阻塞问题，含稳定 ID、具体复现步骤、预期与实际结果、证据。
- `suggestions`：改进建议，不触发自动执行。
- `allow_retry`：true / false 及原因。只有存在范围内阻塞、未触发熔断且预算与授权允许时才可为 true。

PASS 表示本次验收范围通过；PARTIAL 表示部分通过且仍有未验收或阻塞项；FAIL 表示已证实不满足验收；BLOCKED 表示环境或输入导致无法执行关键检查。业务报告各维度另用 PASS / PARTIAL / FAIL / NOT TESTED，不能混用成项目阶段。

返工后只复验列明的 blocking issue，加必要的核心 smoke test；一次任务的 QA 不可反复变成全量新审计。超出范围的建议另交用户决定，不能扩大当前验收标准。

## 停止条件

出现以下任一条件，输出 `AUTO_LOOP_STOPPED`，停止自动交接、返工或重试，交由用户决定继续、改方案或停止：

- 任一计数到上限；更严格的任务预算或运行环境约束优先。
- 同一问题连续出现两次（含首次出现），即使同一错误的重试次数尚未达到 2。
- 连续两轮检查的阻塞问题数量没有减少。
- 拟继续执行但没有新证据。
- 需要改变验收标准。
- 预计下一步使成本超过任务预算；涉及付费且预算未知时先明确预算和授权。

AUTO_LOOP_STOPPED 是执行控制信号，不等于 QA FAIL 或项目 STOPPED；最终通过后也可记录额度耗尽并正常交付，无需再运行。只有用户决定停止项目，才更新项目决策 STOP 与阶段 STOPPED。

Token 预算仅在运行平台提供可靠用量数据及可执行控制时硬执行。没有计量能力时使用交接和返工次数软限制，记录 Token 未知，不得声称平台已经自动限额。预算分别列 Token、API 次数、人民币与人工时间；未知填 null 或 TBD，不填 0。检查成本包括失败与重试，不能只统计成功样本。

## 交接记录示例（虚构格式，不是实际项目记录）

```yaml
task_id: EXAMPLE-001
from: 开发
to: 验证
authorized_by: 总控
goal: 验证约定的导出功能
acceptance: 输出可打开且包含全部约定字段
repo: '<项目仓库>'
ref: '<分支及提交>'
artifacts: ['<产物路径>']
status: 待验收
blocking_issues: []
evidence: ['<开发者自测日志>']
```

总控在同一任务记录另记：本次交接后 handoffs=1、development_reworks=0、full_qa=0，预算仍为用户已批准值。

## 终止记录示例（虚构格式）

```yaml
task_id: EXAMPLE-001
signal: AUTO_LOOP_STOPPED
reason: 同一导出缺字段问题连续出现两次
qa_result: FAIL
handoffs: 3
development_reworks: 1
full_qa: 1
same_error_retries: 0
blocking_issues:
  - id: B-01
    reproduce: 使用约定输入导出并核对字段清单
    expected: 包含全部字段
    actual: 缺少约定字段
    evidence: ['<首次报告>', '<定向复验日志>']
suggestions: []
allow_retry: false
next_action: 等待用户决定继续、改方案或停止；保留累计计数
```
