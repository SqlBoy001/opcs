## 建议工作流（设计，尚未实跑）

真实证据与素材索引 → content.json事实源 → 有因果关系的口播文稿 → 镜头清单 → Explorer → 确定性操作回放/录屏 → 局部裁切与加速 → 版本对比 → 时间轴合成 → 字幕版与干净画面版 → 后配音后重新对齐 → 自检。

优先组合：Cap的录屏表达方式 + 自有镜头清单 + FFmpeg/Remotion合成。MoneyPrinterTurbo借鉴中文流水线组织，short-video-maker只作scene/MCP架构参考。没有发现可直接证明一键完成本案例端到端纪实剪辑的现成方案；这里不作“市面上不存在”的穷尽判断。

镜头清单建议增加：scene_id、叙事目的、evidence_ids、素材路径、source_in/out、裁切焦点、播放速度、叙述文稿、字幕短句、版本标签、后续口播占位。事实源与剪辑时间轴分开维护，既有v2结论不变。

## 内容组织提案
建议先按约2–3分钟主版组织完整过程，再从同一素材剪短版；具体长度服从真实素材密度，不机械套原45–90秒。

| 故事节点 | 展示材料 | 剪辑方法 |
| --- | --- | --- |
| 开场结果与悬念 | 同一动作的早期问题版与后期版 | 先让观众看到差别；没有对应版本就不冒充前后对比 |
| 为什么选漫剧 | 实际赛道比较、调研记录 | 圈出决定性的选择依据；缺历史依据则标今天回顾/待补 |
| 准备与搭台 | 模型分工、脱敏配置、工作台 | 真实操作局部放大；历史未录制内容标当前演示，不能冒充历史现场 |
| 第一轮生成 | 实际脚本→提示词→角色图→分镜→视频 | 重复操作加速或跳切；明确一键范围及人工介入点 |
| 问题与调整 | 同镜头版本、prompt差异、提交/制作记录 | 问题画面→关键改动→修改结果；调整原因须有记录支撑 |
| 最终效果 | v2核实的检查版节选 | 关键动作原速，不用加速遮盖瑕疵；保留未听审/剪辑依赖等边界 |
| 是否继续 | 实际已知费用、剩余问题 | 74.92元非完整成本；只给有证据的判断，下一步标建议 |

竖屏1080×1920是本次设计建议，不是平台硬性规则。大画面展示操作，长提示词局部放大；字幕以短句解释“为什么这样做”，避免整段报告上屏。等待段可考虑4–8倍，关键输入和输出保持可阅读，问题动作原速；这些是拟议节奏，需样段验证。数字人口播只在解释性段落预留空间，不遮挡操作与版本差异。

## 后配音交付约定
先交干净画面版、字幕预览版、scene级口播文稿、可编辑时间轴/SRT。当前字幕时长是临时剪辑时长；拿到实际配音后重新对齐字幕和镜头，不能宣称后贴任何音频都会同步。数字人不是必需项，不把它当成消除模板感的补丁。

## 缺口与下一步
现有v2支持成片、动作、播放器与费用边界，不支持完整历史选赛道、调研、搭台与每轮调整的因果。下一项应先整理真实历史素材清单，区分已存在/可以当前重演/需要补充，随后先做20–30秒“问题→调整→对比”的风格样段再扩展；本轮未自动执行新录制、TTS或渲染，也未调用其他Agent。
